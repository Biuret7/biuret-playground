# My Work usability — 2026-10-13

## Improvements

- Find saved plans by name or topic. Catalog topic searches work in both languages, including after a language switch. Arabic marks and common alef variants are normalized for search.
- Filter unfinished/completed plans and sort by update time, next session date or localized name. A distinct no-match state resets the search and filter without deleting work.
- Cards show readiness, self-reported check counts, percentage, remaining planned minutes, and the next session's learning/practice/review type and part. Focus minutes remain a separate measurement.
- Plan names can be changed in a labelled keyboard-accessible dialog. Names are validated; cancel and Escape keep saved work unchanged.
- Renaming reads the latest workspace, preserving current schedule, checks and focus records. A changed name from another tab rejects a stale edit instead of silently replacing it.
- Search inputs and dialog drafts remain intact during dashboard refreshes. Cards no longer replay their entry animation on each typed character.
- Unreadable/blocked saved data has an explicit recovery state and unknown counts rather than zero counts or empty-plan/favorite claims.
- Compact toolbar, clear pencil controls and logical spacing support RTL and both themes. Phone filtering and sorting share one row where space permits.

## Verification

- 58 automated tests pass. New tests cover planned-minute accounting, session identity, multilingual search, filtering, rename preservation and stale/invalid rename rejection.
- Two controlled local tabs: renamed a synthetic plan in one while the other held a draft. The draft remained present and its stale save was rejected with a recovery message. Existing plan checks stayed at 0/22 and 1/22; focus history stayed at one minute.
- Local browser checked search across language switching, empty completed-filter results, reset, next-date sorting, whitespace validation and Escape cancellation.
- Phone at 390 × 844 checked Arabic/light and English/dark without horizontal overflow. Desktop light/RTL proof: `tmp/playground-my-work-20261013.png` outside the public build.

The unreadable-storage UI is backed by the existing blocked/corrupt-storage model tests and source review; this browser pass did not alter the user's real saved storage to induce failure. No plans were deleted, no backend settings were changed and no external users were contacted.
